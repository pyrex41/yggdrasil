# Prompt: an exported, tested equivalence table for shen-go's natives

This is a self-contained brief to run in a session on `pyrex41/shen-go`.
It is step 2 of [lowering.md](lowering.md) in pyrex41/yggdrasil. Copy
everything below the line.

---

You are working in the shen-go repository, a Go implementation of the Shen
language whose kernel is loaded from KLambda (`kernel/klambda/*.kl`).
At startup `kl.InstallKernelFast()` (in `kl/kernelfast.go`) rebinds 54
kernel functions to Go natives: `arity`, `fn`, `put`, `get`, `map`,
`append`, `reverse`, `element?`, `vector`, `thaw`, and the rest of the
list in that function. Each of those is a claim that the native
implements the KL definition of the same name. Nothing currently tests
the claims one by one. Your job is to make each one a checked,
exported fact so that the Yggdrasil tree-shaker can consume the table as
a declared, verified port-specific lowering.

Read first: `kl/kernelfast.go` (all of `InstallKernelFast` and every
native it binds), `kernel/klambda/` for the KL definitions of the same
names (grep `(defun NAME `), `cmd/kl` (the bare KLambda VM runner),
`cmd/yggdrasil-build/main.go` (how the builder boots), and the existing
test layout under `kl/` and `certification/`.

## Deliverable 1: the table, as data

`kl/equiv.json`, generated by a `go generate` step or written by a test
that fails when it drifts from `InstallKernelFast`, with one entry per
rebound symbol:

```json
{
  "port": "shen-go",
  "kernel": "S42",
  "rows": [
    {"kernel_fn": "reverse", "native": "nativeReverse", "arity": 1,
     "verified": true, "cases": 40,
     "source": "kl/kernelfast.go:nativeReverse"},
    {"kernel_fn": "put", "native": "nativePut", "arity": 4,
     "verified": true, "cases": 40, "effects": ["*property-vector*"],
     "source": "kl/kernelfast.go:nativePut"},
    ...
  ]
}
```

`arity` must match the kernel's arity table for that name. `effects`
lists the globals the native reads or writes, so the consumer can treat
it as impure. A row you could not verify is kept with `verified: false`
and a `reason`.

## Deliverable 2: a differential test per row

`kl/equiv_test.go`: for each row, evaluate the **KL definition** of the
function and the **native** on the same inputs and require identical
results, including identical error behaviour (same error, or both
succeed). The KL side is obtained by loading the kernel file's `defun`
under a fresh name (e.g. `equiv.reverse`) into a VM in which
`InstallKernelFast` has NOT run for that symbol, so the KL body actually
executes; the native side is the rebound symbol. Inputs come from three
sources, in this order:

1. **Boundary cases** per type the function accepts: empty list, one
   element, nested lists, the empty string, a one-character string,
   strings with multi-byte characters, zero, negative and large integers,
   floats where the KL body accepts them, symbols including ones with
   dots and asterisks, vectors of size 0 and 1, `true`/`false`, and for
   higher-order functions (`map`, `fn`, `thaw`) both a KL lambda and a
   native.
2. **Kernel usage**: every call site of the function inside
   `kernel/klambda/*.kl` with literal arguments, extracted mechanically.
3. **Seeded random draws** (a fixed seed, at least 20 per row) from the
   same generators, so a failure reproduces.

Property-list functions (`put`, `get`, `unput`, `bound?`) are stateful:
run both sides against separate fresh `*property-vector*`s and compare
the resulting vectors as well as the return values. `arity` and `fn`
read the kernel's tables: seed both sides identically.

Examples of what a row's test must catch, and you should add each as an
explicit case:

- `(reverse [])` and `(reverse [1])` and a 10,000-element list (a native
  that recurses could overflow where the KL body's tail loop does not, or
  vice versa; both must succeed or both must fail the same way).
- `(hdstr "")`: the KL body raises; the native must raise, not return a
  sentinel.
- `(element? 1 [1.0])`: KL `=` semantics decide; the native must agree
  with whatever the KL body returns on this port.
- `(nth 0 [a b])` and `(nth 3 [a b])`: index base and out-of-range
  behaviour.
- `(map F [])` where F is never called; and `(map F [1 2 3])` where F
  has a side effect, checking the number and order of calls.
- `(put a b c V)` then `(get a b V)` then `(unput a b V)` then `(get a b
  V)` raising; compare the vector contents after each step.
- `(thaw (freeze E))` where E has a side effect: must run exactly once.
- `(vector 0)` and `(vector-> V 0 x)` on a zero-size vector.
- `(shen.string->bytes "λ")`: bytes of the UTF-8 encoding, in order.
- `(string->symbol "*foo*")`, `(symbol? (intern "1"))`.

## Deliverable 3: a KL-level harness the table can be re-checked with

`cmd/kl equiv-check kl/equiv.json`: loads the kernel, runs the same
differential cases from the JSON's own `cases` field (write the cases
out with the table so a consumer can re-run them on another host), and
prints one line per row, `equiv NAME ok cases=N` or `equiv NAME FAIL
case=... kl=... native=...`. Exit non-zero on any FAIL. This is what
Yggdrasil's conformance report will invoke.

## Deliverable 4: the builder installs the natives

`cmd/yggdrasil-build` boots the kernel without `InstallKernelFast`, which
is both slower and, since commit 5edf47e, broken (an interpreted `put`'s
tail call inside `trap-error` escapes the interpreter's recover). Call
`kl.InstallKernelFast()` and `kl.InstallPr()` before the boot loop, as
`cmd/shen/main.go` does, and add a test that the builder boots the
kernel. This is issue #46.

## Constraints

- No change to any native's behaviour in this work. If a differential
  test fails, the row is marked `verified: false` with the failing case
  in `reason`, and the failure is reported; fixing natives is a separate
  change so that the table's first version is an honest audit.
- Keep the JSON schema exactly as above so Yggdrasil can import it.
- Run `go test ./...` and `make certify` (or whatever the repo's kernel
  certification target is) before finishing; both must pass.

## Report

Commit on a branch. In the final report give: the number of rows
verified and unverified, every unverified row with its failing case, the
total number of differential cases, the run time of `equiv-check`, and
the path of the exported JSON.
